# КНС — расчёт перекачки дождевого стока

Статический сайт без бэкенда: `index.html` (одиночный расчёт) и
`cascade.html` (редактор каскада КНС). Данные расчёта — в `static/js/`.
Нормативно-справочные таблицы (коэффициенты покрова/стока по СП 32.13330,
Приложение Ж) вынесены отдельно в `static/js/reference-data.js` — единый
источник истины для расчёта, UI и справки. В модалках справки внизу приведён
блок «Источники данных и формул» (СП 32.13330, рекомендации НИИ ВОДГЕО).

## Шаринг каскада ссылкой (`#s=…`)

Кнопка **«Поделиться»** в шапке `cascade.html` — иконочная, со значком
[nodes-right](https://gravity-ui.com/icons?icon=NodesRight) из gravity-ui
(inline-SVG `currentColor` в стиле остальных `.ic`; после копирования
на 1,5 с значок меняется на галочку через класс `.copied`). Кладёт схему
прямо в адрес:

```
cascade.html#s=d.NPhLg6tZ…          d. — deflate-raw + base64url
cascade.html#s=j.…                  j. — без сжатия (деградация старых браузеров)
```

Как это устроено (`static/js/cascade-io.js`, секция «Шаринг ссылкой»):

1. `stripSharePayload` вычитает из `data` нод значения `NODE_DEFAULTS` и
   не тащит `format`/`version`/`meta` — при загрузке их возвращает
   `migrateNodeData` / подставляет `decodeShareCode`;
2. JSON сжимается `CompressionStream("deflate-raw")` (Chrome 80+, Firefox
   113+, Safari 16.4+, widely available с 2023) и кодируется base64url —
   в адресе только `[A-Za-z0-9-_]`, percent-encoding нулевой;
3. фрагмент после `#` **не отправляется на сервер**: нет 414 от nginx/Apache,
   нет схемы в access-логах и Referer — поэтому бэкенд не нужен;
4. при открытии ссылки `loadInitial()` читает хеш раньше реестра схем,
   прогоняет через `validatePayload` (циклы, типы, связи — как у импорта
   файла) и заводит **отдельную схему** через
   `applyPayload(payload, { asNewScheme: true, name })`; битая ссылка —
   alert + обычная загрузка, ничего не портится.

**Фрагмент — одноразовый носитель.** После применения он убирается из адреса
(`clearShareFragment`, `history.replaceState` с фолбэком на `file://`), а
кнопка «Поделиться» вообще не трогает адрес — ссылка живёт только в буфере
обмена. Иначе `#s=` «приживается» в строке и на F5 плодил бы дубли схемы.
Каноническое состояние редактора — реестр схем в `localStorage` (см. ниже);
ссылка не перезаписывает активную схему, а добавляет новую.

## Библиотека схем (несколько схем в браузере)

Кнопка **«Схемы»** в шапке `cascade.html` открывает список сохранённых в
браузере схем: переключение, переименование, дублирование, удаление,
«+ Новая схема». Хранение (`static/js/cascade-io.js`, секция «Библиотека
схем»; UI — `static/js/cascade-schemes.js`):

- реестр — `kns-cascade:index` = `{ active, items: [{ id, name, updatedAt,
  nodeCount }] }`;
- схема — `kns-cascade:s:<id>` (blob `serializeScheme`), вьюпорт —
  `kns-cascade:v:<id>` (позиция и зум на каждую схему);
- имя в списке: заданное пользователем → `meta.title` из «Сведений» →
  «Схема N».

**Миграция.** Старые одиночные ключи `kns-cascade` / `-n` / `-meta` / `-view`
при первом открытии разово превращаются в первую запись реестра, поэтому
работа текущих пользователей не теряется. Копия пишется с проверкой чтением
(read-back), и старые ключи удаляются **только после** её успеха: если места
не хватило, схема остаётся на легаси-ключе (`LEGACY_ID`) и переезжает при
первом успешном сохранении.

**Открытие ссылки и импорт файла заводят новую схему** (`applyPayload` с
`asNewScheme`), а не заменяют активную — именно это закрывает баг, когда
незавершённая работа затиралась схемой из ссылки. Если новую схему сохранить
не удалось (место/предел), холст не трогается вовсе. Переключение схем
сохраняет каждую, так что терять при переходах нечего.

**Переполнение хранилища.** Квота `localStorage` у origin ~5 МБ, синхронно
её остаток не узнать, поэтому запись схемы отделена от записи реестра и
вьюпорта: провал блоба = схема помечается `unsaved`, в шапке появляется
янтарный баннер «Схема не сохраняется…» с кнопкой «Схемы», а в списке — бейдж
«не сохранена». Провал индекса/вьюпорта — мягче и работу не теряет. Операции
create/delete держат реестр и блобы согласованными (сначала блоб → потом
реестр; при удалении — наоборот), поэтому «фантомных» пустых схем не
появляется. Предел — `MAX_SCHEMES = 50`; в модалке видно занятое место
(`navigator.storage.estimate()`) и размер каждой схемы. Дополнительно
запрашивается `navigator.storage.persist()`, чтобы браузер не вытеснял
данные. Восстановление места снимает баннер автоматически.

## Проверка длины (почему без бэкенда это работает)

Замерялось на реалистичных схемах (имена/описания по-русски, значения
из рабочих диапазонов). «URL» = `deflate-raw` + base64url одного параметра:

| схема | исходный JSON | в ссылке | + вычитание дефолтов |
|---|---|---|---|
| 3/1/2 (водосбор/КНС/участок) | 1 507 симв. | 871 | 712 |
| 8/4/6 | 4 072 | 1 278 | 1 090 |
| 16/8/12 | 8 015 | 1 854 | 1 632 |
| 40/20/30 (90 нод) | 19 850 | 3 484 | **3 159** |

Ориентиры лимитов: дефолтный Apache `LimitRequestLine` — 8192 байта,
nginx `large_client_header_buffers` — 8 КБ на request-line (для query;
фрагмент до сервера не доходит вообще), комфортный QR — до ~1200 симв.
Даже 90-узловая схема влезает с запасом; `SHARE_LIMIT = 6000` символов —
страховка, при превышении кнопка предлагает «Экспорт» в файл вместо ссылки.

Гипотезы **YAML** и **tree.d** ([nin-jin/tree.d](https://github.com/nin-jin/tree.d))
проверены и **отклонены**: на сыром тексте tree.d короче JSON, но после
deflate разница обращается (1 324 против 1 278 на 18-узловой схеме) —
всю синтаксическую избыточность съемиет сжатие, смена формата serialization
ничего не даёт. Решает только само сжатие (×3–4) и вычитание дефолтов (−16 %).

## Тесты

```bash
for f in tests/*.test.js; do node "$f"; done   # все файлы — независимые раннеры
```

`tests/cascade-flow.test.js` (33 проверки) — нода «Доп. приток»: прямоугольный
импульс Q на [t₁; t₂) эмитится кусочно-постоянной GF (изломы попадают в
сегментацию `mixedAnalyticCalc`, станция остаётся в точной аналитической
ветке), пустое t₁ = «с начала события», пустое t₂ = «до конца расчётного
события» (горизонт `rainHorizon` из дождя схемы), подсказки итоговой строки
для всех комбинаций пустых границ, сдвиг через `delay`, миграция данных и
секция отчёта.

`tests/cascade-catch.test.js` (28 проверок) — нода «Водосбор»: произвольные
списки участков сети (трубы, ф. 17: `t_p = t_p_ручн. + 0,017·Σ(l/v)`) и участков
лотка (ф. 16: `t_can = t_can_ручн. + 0,021·Σ(l/v)`; формулы (6)–(7) СНиП
2.04.03-85),
отбрасывание нулевых/мусорных
участков, наличие обеих формул в общей справке и в отдельной справке t_r
(кнопка «?» у заголовка «Расчётная продолжительность дождя»), миграция
legacy-тройки `l1/v1…l3/v3` в массив `segs` (числа не меняются), а также
`z_mid`/`ψ_mid` по составу поверхностей (табл. Ж.6, для водонепроницаемых —
Ж.7: интерполяция по A и n, `F = ΣFᵢ`, контрольный пример ВОДГЕО → 0,201/0,634).
Площадь и коэффициенты вынесены в отдельный раздел «Площадь и коэффициенты
стока» со своей справкой «?» (формулы средневзвешенного значения с подстановкой
и таблицы Ж.6/Ж.7, которые строятся прямо из массивов
`SURFACE_TYPES`/`Z_TABLE_A`/`Z_TABLE_N` — источник истины один и тот же для
расчёта и справки; в режиме «по составу поверхностей» площадь F = ΣFᵢ), плюс
выбор коэффициента стока — переменный z (ф. 20/4) или постоянный Ψ (ф. 12/5):
обе формулы с подстановкой, сравнение Q_r двух режимов и правило 30–40 %.

`tests/cascade-share.test.js` (14 проверок) гоняет реальный код `cascade-io.js`
на DOM-моках: round-trip кодирование/декодирование, strip дефолтов,
валидация восстановленной ссылки, отклонение циклов, base64url-алфавит,
деградация `j.`, обработчик кнопки (clipboard, адрес не трогает),
одноразовость фрагмента, регрессия F5 (свежая работа после правок не
перезаписывается снимком) и главное — **ссылка заводит отдельную схему и не
затирает локальную работу**, 90-узловая схема в пределах лимита.

`tests/cascade-schemes.test.js` (17 проверок) — библиотека схем: миграция
старого одиночного ключа, отсутствие дублей при сохранении, переключение с
загрузкой цели на холст, переименование, дублирование без смены активной,
удаление (последнюю нельзя, активную — переключает на соседнюю), вьюпорт на
схему, создание отдельной схемы из payload (ссылка/импорт) и `loadInitial`
из реестра и из легаси-ключа. Плюс переполнение хранилища (мок
`QuotaExceededError`): пометка «не сохранена» и её снятие, отсутствие
«фантомных» схем, сохранность блоба при провале реестра, безопасная миграция
с легаси и предел `MAX_SCHEMES`.
